Ask about two fighters, score each one, print the winner.

BattleSim.java

The problem

Each fighter gets a combat score and a gear score, each out of 100. Add them for a total out of 200. Higher total wins.

Combat score

Ask whether the fighter is a Warrior or a Mage, then ask for that class's three stats, each 1 to 100.

ClassAsks forFormula
1) Warriorstrength, armor, stamina(2 * strength + armor + stamina) / 4.0
2) Mageintellect, mana, focus(intellect + 2 * mana + focus) / 4.0

Gear score

Ask for the fighter's level and the game's max level (both whole numbers), and a gear multiplier between 0.5 and 1.0 (a decimal).

gear = level / maxLevel * 100 * gearMultiplier

Result

Print exactly one of these:

Fighter 1 wins!
Fighter 2 wins!
It's a draw!

Hints

Every gear score comes out 0.0

level / maxLevel is two whole numbers, so Java does whole-number division. 34 divided by 50 is 0. Same trap as week 2. Make one side a decimal.

Printing one decimal place

Your scores will look like 68.75000000001. Use printf with a %.1f placeholder:

System.out.printf("  combat score = %.1f\n", combat);

%.1f gets replaced by the number rounded to one decimal. \n moves to the next line, because printf does not do it for you.

The totals look like they do not add up

Only the display rounds. Compare the real, unrounded totals when you decide the winner. Printed numbers that look one decimal off are correct and expected.

Why 4.0 and not 4

Same reason as the gear score. If everything in the sum is a whole number, dividing by 4 throws away the decimal part. Dividing by 4.0 keeps it.

Input goes wrong after a number

If you add any text input, nextInt() reads the digits and stops, leaving the Enter key you pressed still waiting. The next nextLine() grabs that and comes back empty. Add one extra input.nextLine(); to swallow it.

Stretch goals

Only once the above works.

  1. Class advantage. Warriors beat Mages in a tie.
  2. Rank the winner. 180 or more is Legendary, 150 is Elite, 100 is Seasoned, below that is Rookie.
